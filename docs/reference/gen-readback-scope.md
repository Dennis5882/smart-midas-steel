# Gen 하중 읽어 오기(엔지니어 하중) — 인식 범위와 해석 후 동작

> 상태: **1단계 + 2단계 구현(2026-10-26, TW·추가 구조 없음)** — 해석 단계 화면 `GenReadPanel`([Gen 하중 불러오기] → 해석 전 확인·조합 용도 지정·단면 변경 확인 → 확정), `domain/genLoads.ts`·`domain/genSections.ts`·`actions/readback.ts`. 최적화·NG 보완은 단면만 PUT. 남은 한계는 아래 각 절.
> 배경: 대만 회의(`docs/taiwan-meeting-2026-10-20.md` F2) — 자동 하중을 바로 믿기보다 엔지니어가 Gen 에서 하중을 넣고 앱이 읽어 와 검토하는 흐름 요청.

## 흐름

1. 앱 → Gen: 「모델 + 자중만」 생성
2. 엔지니어: Gen 에서 하중 케이스·하중·조합 입력
3. 앱: **Gen 불러오기** — 형상 동일성 확인 + 하중·조합 읽기
4. 앱: **불러온 내용 확인(해석 전)** — 모델 차이, 케이스별 하중 형식·합력, 조합 표, 누락 경고, (선택) 앱 자동 하중과 비교
5. 사용자 확인 체크 → 해석(`doc/anal`, 자동 저장 선행)
6. 반력으로 케이스별 하중 합계 확정
7. 설계 검토 → 산출물

## 3. 단계 계획

- **1단계**: 불러오기(형상 동일성 + 하중·조합 읽기) → 확인 화면 → 해석 → 반력 확정 → 부재·접합·사용성(케이스 종류 기준). 내진 특수·ASD 는 전문가 검토. 형상이 바뀌었으면 막음.
- **2단계**: 조합 용도 지정 화면(증폭 지진·중력·ASD, 이름 규칙 자동 추정 + 수정) → 내진 특수 검토 개방, 단면 변경 받아들이기, 최적화·NG 보완을 '단면만 바꾸기' 방식으로.
- 보류: 부재 추가·삭제 모델 받아들이기, 3D 하중 화살표 표시.

## 4. 기술 메모

- 형상 동일성은 기존 `assertGenSync`(13 DB) 에서 하중 DB(`STLD`·`BODF`·`BMLD`·`CNLD`·`LCOM-GEN`)를 빼고 형상 DB 만 비교.
- `LoadInfo` 에 의존하는 설계 코드(`comboKind`·`wind.variants`·`seismic`·`omega`) 는 엔지니어 하중일 때 대체값 필요 — 모든 조합 `basic`, 풍 변형·지진 계수 없음 → 해당 검토는 전문가 검토 이슈.
- 결과 지문·재사용(`reusableResults`) 은 그대로 사용 가능.
- 계산서 PDF 글꼴 축소본에 새 문구 글자 확인(verify-pdf).

## 6. 2단계 구현 메모 (2026-10-26)

- **조합 용도 지정**: 확인 화면 조합 표에 용도 선택(일반·증폭 지진 E′·중력 13.6.1·ASD). 처음 값 `guessComboKind` — 이름에 ASD → asd, 이름에 ′·'·Ω → amplified(계수만으로는 E′ = Ω·E 인지 배율 지진인지 모름 — 증폭으로 잘못 보면 부재 강도 검토에서 빠지므로 일반으로 두고 조합 표에 `seismicFactor` 안내 배지, 2026-10-27 리뷰), 지진 = Gen 종류 `E` 만(EH·EV 토압 아님)·풍 = `W` 만(WP 수압 아님), D + 활하중(L·LR)만이고 활하중 계수 ≤ 1 또는 이름에 13.6 → gravity, 그 밖 basic. 앱 자체 조합 155개(ASD 선택 시 포함)에 적용하면 앱 용도와 전부 같음(회귀). Ω = 증폭 지진 조합의 방향별 E 계수 최대. 확정 시 `info.comboKind` = 지정값 → 가새·기둥 축력 13.4.1·주각 13.4.5·처마 13.6.1 용량 설계·ASD 병행이 지금과 같이 동작. 처마 V(13.3-1) 상한은 이름으로 13.3-1 을 가릴 수 없어 증폭 지진 조합 전부(보수적), 13.7.2-3a 소요 소성 회전각은 엔지니어 지진 케이스가 V 인지 V* 인지 몰라(지진 변위각과 같은 이유) θE 를 쓰지 않고 상한 `θp,req ≤ 0.01 rad` 만 표시(처마는 회전능력 시험 근거로 원래 `expert`). 지진 변위각(2.16.1)·기초 예비검토는 계속 미검토(scope warn `genLoads`).
- **단면만 바꾸는 최적화·NG 보완**: `resendModel` → 엔지니어 하중 모델이면 `updateSections` — 자동 저장 후 SECT·ELEM 만 PUT(doc/new 없음, 요소·절점 번호와 BMLD·CNLD·조합 유지, 자중은 Gen 이 새 단면으로), UNIT·MATL·NODE·FRLS·CONS·DSTL(`GEN_FIXED_DBS` — 읽기 형상 확인과 같은 목록)이 보낸 것과 다르면 `SectionUpdateError`(`rb_geometry`)로 거부, PUT 직전 결과를 비우고 `S.built` 를 새 객체로(중간 실패 때 이전 결과가 지금 모델 결과로 남지 않음 — 다음 해석 직전 동일성 검사가 차이를 잡음), 다시 읽어 확인(SECT 는 남은 옛 번호 허용 — 동일성 기준 = 다시 읽은 SECT), 단면 출처(SECTIONALL) 대조, `S.built` 의 spec·model·info 갱신 — 요약은 확정 때 읽은 하중 표 전부(`Built.genRaw`, 합산 못 하는 표 포함)로 다시 만들고 조합 용도는 확정한 값 유지. 회귀 `verify-genloads.ts` 55.

## 7. 2단계 C — Gen 에서 바꾼 단면 받아들이기 (2026-10-26)

- 읽기 때 형상 확인은 SECT·ELEM 을 뺀 표(UNIT·MATL·NODE·FRLS·CONS·DSTL)만, SECT·ELEM 은 `reviewGenSections`: 요소 집합·형식·재료·절점·각도가 같고(SECT 번호만 달라도 됨), 역할(기둥·지붕보…)마다 단면 하나(앱 모델 구조 `spec.sections[role]` — 모든 형식에서 요소 단면 = 역할 단면 확인), 앱 단면 목록(카탈로그·국가/역할/재료 목록, Gen 이름 = 앱 이름에서 공백 제거)에 있고, 단면 정의(형상·DB·DB 단면 이름·자료 형식·오프셋)가 앱이 만드는 것과 같으면 받아들인다. 해석 옵션(전단변형·뒴)은 비교하지 않고 다르면 확인 화면에 안내(`rb_sect_options`). 역할 단면 변경이 없어도 확정하면 읽은 SECT·ELEM 이 동일성 기준(옵션만 바꾼 단면·같은 이름 새 번호가 다음 해석을 막지 않게). 트러스 하현재·웨브를 비워 두면 기본 단면(`withTrussDefaults`)과 비교. 막는 이유: `rb_sect_elements`·`rb_sect_mixed`(역할 안에서 섞임)·`rb_sect_unknown`(목록 밖)·`rb_sect_definition`.
