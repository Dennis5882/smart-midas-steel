# 대만 회의 기록 (2026-10-20)

> 출처: 회의 음성 자동 기록(Tiro, 중국어·한국어 혼재). 자동 인식 오류가 많아 아래는 요지 정리다. 「封立」는 문맥상 「風力」(풍하중)의 오인식으로 보았다.
> 상태: **기록만 — 후속 논의 필요.** 아래 내용으로 아직 구현·계획을 바꾸지 않았다.

## 1. 앱(Smart MIDAS Steel 공장)에 대한 평가

- **자동 모델링은 매우 매력적이다.** 형상·단면을 고르면 Gen 모델이 바로 만들어지는 것만으로도 실무에 도움이 된다. 3일 만에 이 정도를 만든 점도 높게 평가했다.
- **하중·해석·계산서까지 한 번에 자동으로 끝내는 것은 위험하다.**
  - 기술자가 검토하지 않은 「기계가 만든 계산서」는 안전하지 않다. 데모(광고)용으로는 좋지만 최종 성과물이 될 수 없다.
  - 결과가 틀리면 「MIDAS 프로그램 결과가 틀렸다」는 말을 듣게 된다.
- **지진하중** — 위치(지역 계수)만으로는 부족하다. 구조 형식, 토질 등 조정 계수가 많다. 주기는 고유치(모달) 해석으로 구해야 하는데, 현재는 고유치 해석 없이 근사 주기를 쓰므로 지진력이 틀린다고 봤다. 현재는 「지역 계수만 잡는 수준」이라는 평가다.
- **풍하중** — 「100% 맞지 않는다」, 손계산 뒤 다시 고쳐야 하므로 최종 결과가 될 수 없다는 의견이다.
- **결론**: 단면 단계까지(형상·재료·단면 → Gen 모델 생성)는 OK. 지진·풍 하중 자동 계산은 큰 의미가 없고, 틀리면 오히려 곤란하다.

## 2. 제안받은 작업 흐름 (단계별 분리)

1. **모델링만** — 형상·재료·단면(+ 자중 정도)으로 Gen 모델을 만들어 내보낸다. 하중은 넣지 않는다.
2. **기술자가 Gen에서 하중 입력·해석** — 공장은 하중 조건이 현장마다 크게 달라 기술자가 최종 확인해야 한다.
3. **앱이 Gen 모델·결과를 다시 읽어 온다** — 읽어 온 뒤 최적화(BOM 중량 절감)를 하고 계산서·물량을 출력한다.

- 「일괄로 다 끝낼 필요 없이 단계로 나눠라」는 요청이다. 최적화는 Gen 안에서도 할 수 있지만, 결과를 읽어 와서 계산서·물량을 내면 유용하다는 의견이다.
- 물량(BOM, 몇 톤)은 모델 기반이라 기존보다 정확할 것으로 기대했다.
- 계산서는 현재 정해진 양식(템플릿)이 없다.
- 데모에서는 「모두 자동」을 보여 줘도 되지만, 실무에서는 기술자가 최종 확인한다.
- 회의 후반에는 「최적화는 일단 보류」, 「지금 버전을 먼저 공개해도 된다(모델링이 빨라지는 효과)」는 말도 있었다.

## 3. 기타 의견

- **골조(다층 프레임) 데모** — 의미가 적다. 구조는 건축 도면이 지배하므로 앞으로는 건축 도면을 스캔해 구조를 만드는 방향이어야 한다. 공장은 OK.
- **RC 기둥받침(墩柱/短柱) 아이디어** — 일부 공장은 강재 기둥 아래 일정 높이를 RC로 만든다(베이스플레이트 → RC 기둥받침, 높이 약 0.5 m ~ 1.1 m). 강재 기둥이 너무 길면 약해서 보강이 필요하고 비싸지기 때문이다. 높이(절점)를 지정해 그 아래를 RC로 하는 기능을 생각해 볼 만하다. 다만 「지금은 하지 말자」는 취지의 발언도 있었다.
- **언어** — 영어·번체 전환을 제공할 것. 국제 기술자 고객이 늘고 있다. 번체 번역이 어색한 곳이 있다.

## 4. 본 앱과 별개인 MIDAS 대만 현안 (참고)

- MIDAS API 3종(플러그인 / 웹 API / mConnector). mConnector는 담당자 퇴사로 통합이 중단돼 버전 간 문제가 있다.
- 대부분의 회사는 자체 Excel 보고서를 쓴다. 교량 부서는 기존 Excel 파일 기반 작업을 원한다. 웹 API로 옮기는 것은 재작업 부담이 있다.
- Gen UI 대만 현지화: 자주 쓰는 기능 위주로 번역했다. JSON 2만여 건 중 확인이 필요한 용어를 Excel로 정리했다. 대륙식 용어가 아직 많고, 이달 중 최종본을 받을 예정이다.
- Gen·Civil 출력 보고서의 글자 겹침(叠字) 문제를 대만 쪽에서 고칠 수 있는지, 본사가 고쳐야 하는지 문의했다. 계산서에 보고서를 인쇄해 넣는 경우가 많다.

## 5. 후속 논의 항목 (제안)

| # | 항목 | 현재 앱 상태 | 논의할 점 |
|---|---|---|---|
| F1 | 「모델만」 단계 (하중 없이 Gen 생성) | 하중·조합을 항상 함께 보냄 | 하중 없이 내보내기 옵션, 자중만 둘지 |
| F2 | Gen 모델·결과 다시 읽어 오기 | 앱이 보낸 모델만 다룸(Gen에서 바뀌면 차단) | 기술자가 넣은 하중·조합·단면을 읽어 와 검토·최적화·계산서. 읽기 범위와 검증 방법 |
| F3 | 지진하중 | 정적 등가, 근사 주기 | 고유치 해석 주기 사용(Gen 모달), 또는 지진·풍 자동값을 「참고값」으로만 표시 |
| F4 | 계산서 위치 | 계산서는 기술자 검토 전 초안 | 양식 템플릿, 「초안」 표시 강화 |
| F5 | RC 기둥받침 | 없음 | 수요·우선순위 확인 후 결정 |
| F6 | 영어·번체 | 4개 언어 지원 중 | 번체 용어 검수 결과 반영 |
